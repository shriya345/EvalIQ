# Evaluation methodology

The case manifest defines the question, expected value, comparison mode, required source and expected evidence field. Candidate outputs live in separate files or arrive through the CLI or API. Every run retains a snapshot per case. The standard output object contains answer and a list of citation IDs. The grader records each check, any failure names, and an overall pass requiring every applicable check to pass.

Exact matching requires equal values and types. Normalized text folds case and collapses whitespace. Numeric matching accepts a finite JSON number within 0.01 absolute units of the reference and excludes booleans. All citations must refer to known documents. Coverage requires the specified source for answerable cases. A numeric answer must agree with the designated structured field in a cited source. Unsupported numeric answers fail. The checks cover structured values only. They cannot detect a plausible false claim embedded in prose.

The fictional support corpus includes archived and current warranty terms, missing information and an instruction embedded in a question. The ledger corpus contains four numeric questions and one missing value. The filings corpus uses six FY2024 figures and one unavailable price forecast. It pairs FinPulse's exported expected and actual answers with six separately looked-up source fact rows. A null forecast is a valid explicit abstention. Filing URLs and accession numbers are in fixtures/documents.json. No live model judged any case.

Task metrics use one started task per application and trace. The latest response supplies status, end-to-end latency, cost and tokens. Missing responses remain in the denominator. Error rate counts started traces with any recorded error, including tool failures. A recovered tool error can coexist with task success. Tool failure rate uses tool calls as the denominator. Average, median and interpolated P95 use observed terminal durations. The agent timeline also displays individual stage timings. Missing tool timings or child-only usage do not automatically become task totals.

Known spend and token totals sum available terminal values. Cost per request averages priced responses. Cost per success divides total spend by successful tasks only when every started task is priced. Counts accompany partial metrics. Explicit zero is a known observation. In the event-level SQL workbook, response latency includes individual response events; task-level UI metrics choose the final response on a repeated trace.

The comparison uses the intersection of visible case IDs. The two synthetic configurations have identical case lists. Synthetic telemetry deliberately includes missing completions independently of candidate answer files. Evaluation coverage counts scored case outputs, including outputs supplied offline. The filings benchmark has recorded answers but no linked task-level consumption or expenditure. Saved benchmark runs are displayed separately from date-filtered telemetry. Date and metadata filters apply to individual event rows, so a trace spanning the selected date boundary can appear incomplete.

## Retrieval and experiment metrics

Let G be the independently labeled relevant passage set and H the first K positions. A repeated passage earns credit once. Precision@K is the relevant hits divided by K, including unfilled slots. Recall@K is the relevant hits divided by the size of G. Hit@K is one if any relevant passage appears. Reciprocal rank is one divided by the first relevant rank, or zero for a miss. MRR@K averages reciprocal rank over labeled queries. nDCG discounts gain at rank i by log2(i+1), with gain 2^grade−1, and divides the observed sum by the ideal sum. The runner supports graded labels; the shipped labels are binary. With known positives and no results all these scores are zero. With no positive labels the retrieval scores are undefined and excluded. The financial metric treats each labeled chunk as a relevant item, including overlapping windows.

BM25 uses k1=1.2 and b=.75. Dense retrieval uses normalized cosine similarity. Hybrid retrieval adds 1/(60+rank) across the two orderings. The optional cross-encoder reranks the best five fusion results for K=3. Ties break by sorted passage ID. Retrieval latency uses a monotonic timer after index construction. End-to-end latency includes retrieval, inference and scoring. Token counts come from llama.cpp. Pricing stays unknown unless a rate is explicitly configured.

Experiments keep raw candidate text, parsed output, rank order, scores, labels and aggregate denominators. Correctness requires the expected scalar and a valid response structure. Citation validity requires that each returned citation ID was actually retrieved. Coverage measures the fraction of required labels cited. Citation support requires full coverage, valid citations and the designated numeric fact check when applicable. These rules cannot establish semantic entailment. Error rate measures execution exceptions. Task completion measures valid structured output, so a schema error can occur even when inference finished. Threshold checks require the same dataset digest, evaluation method, generation mode, K and case IDs. Partial coverage is reported explicitly. The P95 threshold is evaluated on the aggregate quantile; its listed slower cases are diagnostic.
