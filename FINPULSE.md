# FinPulse integration

The local FinPulse producer defines schema version 1.0 in research.py and exports examples/telemetry.schema.json. Both its own examples/telemetry.jsonl and a second export generated by its deterministic AAPL research workflow were imported into EvalIQ. Each export contained four events. The second export is bundled as fixtures/finpulse-recorded.jsonl. Its source database was copied using SQLite backup and only the copy was used to run the workflow.

| FinPulse event | EvalIQ event | Interpretation |
| --- | --- | --- |
| research_started | request | Task root |
| agent_run | agent_run | Agent step with independent timing |
| research_completed | response | Terminal task status |
| evaluation | evaluation | Recorded assessment event |

The adapter activates for application “FinPulse AI”. It preserves the trace, session, event and parent identifiers, token_usage_source, prompt version and evidence IDs. Unrecognized event kinds generate an invalid-line report. The observed deterministic run reported agent timings and left terminal cost and token usage unspecified. Stage timings can be inspected in the trace explorer.

Use python cli.py import /path/to/telemetry.jsonl after the producer closes or flushes its export. Reimporting the same file reports duplicates. The financial filings case pack uses the recorded single-extraction and extraction-with-numeric-verification workflows in FinPulse's examples/evaluation.json. Neither workflow calls a paid provider.

## Recorded document retrieval

FinPulse emits schema 1.0 tool_call events named rag.bm25, rag.semantic, rag.rrf and rag.rrf_rerank. The evaluation_case_id identifies the query. evidence_ids are emitted in ranked order. Agent steps carry model and usage when observed. The final response carries cited IDs and end-to-end latency. FinPulse omits numeric similarity scores from the paired evaluation export. EvalIQ retains them as null. Its generic retrieval object also accepts a score per passage when a producer supplies it.

The final RAG capture pairs 220 events with 80 trials from FinPulse's eval/document-runs.json. The 49-event live agent export remains separate. To reproduce the enrichment from matching producer snapshots, run finpulse_rag.py with the raw JSONL, document-runs.json, document-cases.json, chunk-catalog.json.gz, output JSONL and output metric JSON, in order. Import the resulting enriched JSONL. The enriched record supplies the filing accession and recorded answer. Replay preserves the event count. The new tables are additive for existing SQLite files. FinPulse source and databases were read only.
